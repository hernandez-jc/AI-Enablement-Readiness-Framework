# 03 — Gobernanza

> **Dimensión 03 del AI Enablement Readiness Framework**
> **Pregunta central:** ¿Existen controles, responsabilidades y criterios adecuados para utilizar IA de manera responsable?

---

## 1. Propósito de esta dimensión

La gobernanza establece las condiciones bajo las cuales la organización puede utilizar inteligencia artificial de manera responsable, controlada y alineada con sus obligaciones.

El acceso a herramientas de IA no garantiza que su utilización sea apropiada.

Una organización necesita definir, según corresponda:

* qué usos están permitidos;
* qué usos requieren restricciones;
* quién puede utilizar determinadas herramientas;
* quién es responsable de las decisiones;
* qué información puede utilizarse;
* qué controles deben aplicarse;
* cuándo se requiere supervisión humana;
* cómo se gestionan los riesgos;
* cómo se monitorea el uso.

### Pregunta orientadora

> **¿Existen controles, responsabilidades y criterios adecuados para utilizar IA de manera responsable?**

---

# 2. Gobernanza como condición de AI Enablement

La gobernanza no debe considerarse únicamente como una función de cumplimiento.

También es una condición para que las personas puedan utilizar IA con claridad sobre:

* lo que pueden hacer;
* lo que no deben hacer;
* cuándo necesitan autorización;
* cuándo deben verificar un resultado;
* cuándo deben escalar una situación;
* quién tiene la responsabilidad final.

Una gobernanza poco clara puede limitar la adopción.

Una gobernanza excesivamente restrictiva también puede dificultar la experimentación y el aprendizaje.

Por eso, el objetivo es establecer **condiciones claras y proporcionales al riesgo**.

---

# 3. Qué evalúa esta dimensión

El assessment busca identificar señales relacionadas con la preparación de la organización para gobernar el uso de IA.

| ID     | Criterio                               | Qué busca determinar                                                                   |
| ------ | -------------------------------------- | -------------------------------------------------------------------------------------- |
| GOV-01 | Políticas y lineamientos               | Si existen reglas claras para el uso de IA                                             |
| GOV-02 | Roles y responsabilidades              | Si están definidas las responsabilidades relacionadas con IA                           |
| GOV-03 | Gestión de riesgos                     | Si existen mecanismos para identificar y gestionar riesgos                             |
| GOV-04 | Privacidad y protección de información | Si existen criterios para proteger información utilizada con IA                        |
| GOV-05 | Seguridad                              | Si se consideran controles de seguridad apropiados                                     |
| GOV-06 | Uso responsable                        | Si existen criterios para orientar el uso responsable de IA                            |
| GOV-07 | Supervisión humana                     | Si se define cuándo y cómo debe intervenir una persona                                 |
| GOV-08 | Cumplimiento                           | Si el uso de IA considera las obligaciones aplicables                                  |
| GOV-09 | Monitoreo                              | Si existe capacidad para observar y revisar el uso de IA                               |
| GOV-10 | Gestión y actualización                | Si las reglas pueden evolucionar conforme cambian herramientas, riesgos y casos de uso |

Estos criterios permiten observar la gobernanza como una capacidad organizacional.

---

# 4. GOV-01 — Políticas y lineamientos

### Qué significa

Evalúa si la organización cuenta con reglas y orientaciones suficientemente claras para el uso de IA.

Los lineamientos pueden abordar:

* herramientas autorizadas;
* usos permitidos;
* usos restringidos;
* información que puede utilizarse;
* responsabilidades;
* revisión humana;
* reporte de incidentes.

### ¿Por qué importa?

Cuando las reglas son ambiguas, las personas pueden interpretar de manera diferente qué constituye un uso apropiado.

### Relación con AI Enablement

Las políticas deben ser suficientemente claras para orientar el comportamiento sin convertirse en un obstáculo innecesario para usos legítimos.

---

# 5. GOV-02 — Roles y responsabilidades

### Qué significa

Evalúa si existen responsabilidades claras relacionadas con:

* aprobación;
* supervisión;
* gestión;
* mantenimiento;
* evaluación;
* escalamiento;
* toma de decisiones.

### ¿Por qué importa?

La introducción de IA puede modificar responsabilidades existentes y crear nuevas necesidades de coordinación.

Debe quedar claro:

> **¿Quién responde por qué?**

La ausencia de una respuesta clara puede convertirse en una barrera para la adopción.

---

# 6. GOV-03 — Gestión de riesgos

### Qué significa

Evalúa si la organización puede identificar y gestionar riesgos asociados con los casos de uso de IA.

La evaluación puede considerar:

* naturaleza del caso de uso;
* impacto potencial;
* probabilidad;
* controles existentes;
* supervisión;
* mecanismos de escalamiento.

### Relación con el assessment

Una puntuación baja no indica automáticamente una necesidad de capacitación.

Puede revelar una brecha de:

* procesos;
* políticas;
* responsabilidades;
* controles;
* capacidades;
* tecnología.

---

# 7. GOV-04 — Privacidad y protección de información

### Qué significa

Evalúa si existen criterios para proteger información utilizada por sistemas o herramientas de IA.

La organización debe poder determinar, según corresponda:

* qué información puede introducirse en una herramienta;
* qué información requiere protección adicional;
* qué restricciones existen;
* quién puede utilizar determinados datos.

### Relación con la dimensión de Datos

Esta dimensión se conecta directamente con **01 — Calidad y preparación de datos**.

Los datos pueden ser técnicamente accesibles y, al mismo tiempo, estar sujetos a condiciones específicas de utilización.

---

# 8. GOV-05 — Seguridad

### Qué significa

Evalúa si se consideran controles de seguridad apropiados para las herramientas, sistemas y flujos relacionados con IA.

Puede involucrar:

* acceso;
* autenticación;
* protección de información;
* gestión de permisos;
* controles sobre herramientas;
* monitoreo.

### Relación con Tecnología

La gobernanza establece criterios y responsabilidades.

La tecnología proporciona mecanismos para implementar esos controles.

Por lo tanto:

> **Gobernanza y tecnología deben funcionar de manera coordinada.**

---

# 9. GOV-06 — Uso responsable

### Qué significa

Evalúa si la organización ha definido expectativas claras sobre el uso responsable de IA.

Puede incluir criterios relacionados con:

* revisión humana;
* transparencia;
* uso apropiado;
* identificación de riesgos;
* protección de información;
* evaluación de resultados;
* escalamiento.

### Relación con Skills y talento

Las políticas por sí solas no garantizan un comportamiento adecuado.

Las personas necesitan comprender y aplicar las reglas.

Por eso existe una relación directa entre:

```text id="m6b1yz"
Gobernanza
    ↓
Reglas y criterios
    ↓
Comprensión
    ↓
Aplicación
    ↓
Comportamiento
```

---

# 10. GOV-07 — Supervisión humana

### Qué significa

Evalúa si la organización define cuándo debe existir intervención o revisión humana.

La necesidad de supervisión puede depender de:

* tipo de tarea;
* nivel de riesgo;
* impacto de la decisión;
* naturaleza del output;
* consecuencias de un error.

### ¿Por qué importa?

La automatización no elimina necesariamente la responsabilidad humana.

La organización debe determinar cuándo una persona debe:

* revisar;
* validar;
* aprobar;
* corregir;
* rechazar;
* escalar.

---

# 11. GOV-08 — Cumplimiento

### Qué significa

Evalúa si el uso de IA considera las obligaciones y requisitos aplicables a la organización.

Esto puede relacionarse con:

* políticas internas;
* obligaciones contractuales;
* requisitos regulatorios;
* controles organizacionales;
* requisitos específicos del sector.

### Relación con el assessment

El assessment puede identificar una posible brecha, pero no sustituye una evaluación jurídica, regulatoria o de cumplimiento cuando esta sea necesaria.

---

# 12. GOV-09 — Monitoreo

### Qué significa

Evalúa si la organización tiene capacidad para observar y revisar el uso de IA después de su implementación.

Puede incluir:

* seguimiento;
* revisión;
* documentación;
* indicadores;
* reporte de problemas;
* identificación de incidentes;
* evaluación periódica.

### ¿Por qué importa?

La gobernanza no termina cuando una herramienta o caso de uso es aprobado.

Las condiciones pueden cambiar.

También pueden cambiar:

* herramientas;
* procesos;
* datos;
* riesgos;
* usuarios;
* casos de uso.

---

# 13. GOV-10 — Gestión y actualización

### Qué significa

Evalúa si las políticas, controles y responsabilidades pueden actualizarse a medida que evoluciona el uso de IA.

La gobernanza debe ser capaz de responder a cambios en:

* tecnología;
* herramientas;
* procesos;
* casos de uso;
* riesgos;
* regulación;
* capacidades organizacionales.

### Principio

> **La gobernanza de IA debe ser adaptable, no estática.**

---

# 14. Interpretación de los resultados

Una puntuación baja en Gobernanza identifica una posible condición que requiere investigación.

No debe interpretarse automáticamente como:

> "Necesitamos capacitar al personal."

La lógica correcta es:

```text id="q6t8p2"
Score bajo
    ↓
Identificar área afectada
    ↓
Investigar la causa
    ↓
Determinar la intervención
```

La causa puede estar relacionada con:

* ausencia de políticas;
* responsabilidades poco claras;
* procesos insuficientes;
* controles tecnológicos;
* conocimiento;
* habilidades;
* supervisión;
* gestión del riesgo.

Por lo tanto:

> **GOV score bajo ≠ automáticamente capacitación.**

---

# 15. Conexión con el assessment app

La aplicación de assessment proporciona una primera lectura sobre la preparación de la organización en materia de gobernanza.

Los resultados pueden ayudar a identificar:

* fortalezas;
* posibles brechas;
* áreas prioritarias;
* diferencias entre grupos;
* temas que requieren investigación adicional.

La aplicación no pretende determinar automáticamente si una organización cumple con todas sus obligaciones.

Su función es:

> **identificar señales que permitan orientar una conversación diagnóstica más profunda.**

---

# 16. Relación con Skills y talento

Gobernanza y capacidades humanas están estrechamente relacionadas.

La organización puede tener políticas excelentes y, sin embargo, presentar problemas de aplicación si las personas:

* desconocen las reglas;
* no saben cuándo aplicarlas;
* no reconocen una situación de riesgo;
* no saben cuándo escalar;
* no saben evaluar un resultado.

Por eso:

```text id="l5f5rj"
Gobernanza
     +
Skills
     ↓
Uso responsable
```

La brecha puede encontrarse en la política, en la capacidad de aplicarla o en ambas.

---

# 17. Relación con Datos

La gobernanza determina condiciones para el uso de los datos.

La relación puede representarse como:

```text id="q9x7kk"
Datos disponibles
      ↓
¿Pueden utilizarse?
      ↓
Condiciones de uso
      ↓
Controles
      ↓
Aplicación
```

Esto refuerza la conexión entre:

**01 — Calidad y preparación de datos**

y

**03 — Gobernanza.**

Una organización puede tener datos de buena calidad y, aun así, no estar preparada para utilizarlos en un determinado caso de uso.

---

# 18. Relación con Tecnología e infraestructura

La gobernanza establece qué debe controlarse.

La tecnología ayuda a implementar esos controles.

Por ejemplo:

| Necesidad de gobernanza   | Posible soporte tecnológico              |
| ------------------------- | ---------------------------------------- |
| Control de acceso         | Gestión de identidades y permisos        |
| Protección de información | Controles de seguridad                   |
| Monitoreo                 | Registros e indicadores                  |
| Supervisión               | Flujos de revisión                       |
| Gestión de herramientas   | Administración y control de aplicaciones |

La solución tecnológica debe estar alineada con los requisitos organizacionales.

---

# 19. Preguntas para profundizar durante el workshop

Los resultados pueden utilizarse como punto de partida para preguntas como:

1. ¿Qué usos de IA están actualmente permitidos?
2. ¿Qué usos están restringidos?
3. ¿Quién establece las reglas?
4. ¿Quién es responsable de cada caso de uso?
5. ¿Cómo se identifican y gestionan los riesgos?
6. ¿Cuándo se requiere revisión humana?
7. ¿Qué información puede utilizarse con herramientas de IA?
8. ¿Cómo se reportan problemas o incidentes?
9. ¿Cómo se monitorea el uso?
10. ¿Cómo se actualizan las reglas cuando cambian las herramientas o los riesgos?

Estas preguntas permiten pasar de una puntuación general a una conversación específica sobre la capacidad de gobernanza.

---

# 20. Conexión con el Training Needs Analysis

Los resultados de Gobernanza pueden revelar posibles necesidades de aprendizaje, pero primero debe investigarse la causa.

Por ejemplo:

```text id="x7b0bz"
Brecha de Gobernanza
        ↓
¿Existe una política?
        ↓
No → Intervención de gobernanza
        |
       Sí
        ↓
¿Las personas la conocen?
        ↓
No → Posible necesidad de aprendizaje
        |
       Sí
        ↓
¿Pueden aplicarla correctamente?
        ↓
No → TNA / desarrollo de capacidades
```

Esta lógica mantiene la separación entre:

**brecha organizacional → causa → intervención.**

---

# 21. Implicaciones para AI Enablement

Una gobernanza efectiva debe permitir que las personas sepan:

* qué pueden hacer;
* qué deben evitar;
* qué deben verificar;
* cuándo necesitan autorización;
* cuándo necesitan supervisión;
* cuándo deben escalar.

Esto convierte la gobernanza en una condición práctica para el uso cotidiano de IA.

No es solamente un documento.

Debe poder traducirse en **comportamientos observables dentro del trabajo**.

---

# 22. Principio clave

La pregunta no debe ser solamente:

> **"¿Tenemos una política de IA?"**

Debe ser:

> **"¿Las personas y los sistemas cuentan con reglas, responsabilidades y controles suficientemente claros para utilizar IA de manera apropiada en cada contexto?"**

Esta distinción permite evaluar la gobernanza como una capacidad real y no solamente como la existencia de documentación.
